# MCP

rstream MCP is a connectivity layer for AI agents. It exposes rstream operations as explicit tools while keeping network authority, project scope, device trust, and cleanup semantics in the rstream runtime instead of in prompts or ad hoc shell commands.

There are two related surfaces, not two interchangeable deployments of the same server.

| Surface | Primary role | Deliberate boundary |
| --- | --- | --- |
| `rstream mcp serve` | Trusted workstation and device operations over stdio | Uses local config, project context, private dialing, WebTTY identities, known-server pins, trusted-device material, and local E2E grants |
| Hosted `/api/mcp` | OAuth-scoped Control Plane automation over Streamable HTTP | Has no local shell, private dialer, filesystem sidecar, E2E private keys, or recording decrypt grants |

The local surface is the default when an agent can execute the CLI. Hosted MCP is the fallback for agent runtimes that can call HTTPS but cannot run a device-local process. This is especially important for WebTTY: hosted can inventory servers, manage registered records, run bounded non-E2E commands, read session metadata, export non-E2E recordings, and coordinate control requests; E2E execution and decryption remain local.

## Shared contract

Both surfaces negotiate MCP `2025-11-25`. Shared tools have identical names, titles, and behavior annotations. Input properties and required fields are identical where the operation is genuinely the same; differences are retained only for surface authority, such as local project selectors and E2E identity options versus hosted OAuth project scope.

Every structured tool result is a JSON object and has an object-root `outputSchema`. Collections use semantic keys such as `workspaces`, `projects`, `events`, `servers`, and `sessions` rather than a generic `result` wrapper. WebTTY results identify their source with `surface: "cli"` or `surface: "hosted"`. Registered-server enrollment is consistently returned under `enrollment`.

Tool descriptors include explicit read-only, destructive, idempotent, and open-world hints. These describe behavior for agent planning; they are not authorization controls. Invocation status metadata is short enough for MCP clients to display, and the hosted surface mirrors OAuth security schemes in `_meta` for clients that still read the compatibility location.

Tool execution failures use MCP tool results with `isError: true`. A WebTTY command that fails after starting keeps bounded stdout and stderr, reports a safe `error_kind`, and never discards useful partial output. The hosted collector redacts its delegated connect token before truncation and never returns the authenticated dial URL.

## Local setup

Register the stdio server with Codex:

```bash
rstream codex setup
rstream codex setup --verify
```

Setup preserves explicit `RSTREAM_API_URL`, `RSTREAM_CONFIG`, and `RSTREAM_CONTEXT` values. `--verify` starts a fresh configured command, performs `initialize`, sends `notifications/initialized`, and calls `tools/list`; it does not invoke rstream tools or require network access. MCP stdio servers are child processes bound to their Codex task. After every CLI upgrade, open a new task or reload Codex and run a real read-only tool call: a pre-existing task continues executing the binary version it started with even when the signed package-manager path now points to a newer release.

On a workstation, use `rstream_runtime_prepare` to create or repair the selected project context. It uses the login credential stored in the CLI config and does not mint a short-lived delegated token. If several projects are available and the user did not identify one, the agent must present the choices instead of inferring a default from names.

The device-only tools cover local tunnel lifecycle, full WebTTY and filesystem operation, remote-local service exposure, and remote MCP discovery/calls. Direct authenticated-E2E WebTTY targets use the local known-server store and identities; workspace-managed sessions use trusted-device material and grants available on that device.

## Hosted transport and authorization

Hosted MCP is served at `/api/mcp` with JSON responses over Streamable HTTP. It validates the `Origin` header when present, rejects a foreign origin with HTTP 403, and requires the negotiated `MCP-Protocol-Version` on post-initialization requests. Valid notifications return HTTP 202 without a body. Malformed JSON and invalid JSON-RPC requests remain distinct protocol errors.

Hosted tools declare their minimum OAuth scopes. Authentication and resource restrictions are enforced server-side; annotations and client-side tool allow-lists are only advisory. E2E targets fail with `requires_local_trusted_mcp`, which means the operation must move to a trusted local surface—not that key material should be uploaded.

## Publication and secrets

`rstream mcp publish` exposes the device surface at `/mcp` through a token-protected tunnel. Use a short-lived token scoped to the exact tunnel and path. Publishing currently exposes the complete local tool set, so it is appropriate only for a trusted consumer with an explicit rstream authorization boundary.

Two hardening items remain intentionally open in [TODO](../TODO): server-enforced tool subsets for published or less-trusted consumers, and out-of-band delivery handles for token and TURN credential material. They must be solved together before treating published MCP as a safe browser-agent delegation surface. Descriptors or client allow-lists do not close either gap.

## Validation

The Go suite validates framing, JSON-RPC recovery, descriptor completeness, object-shaped structured content, annotations, invocation metadata, and partial WebTTY output:

```bash
go test ./...
go test -race ./cmd/rstream/cmd
go vet ./...
```

The hosted suite validates Streamable HTTP behavior, OAuth descriptors, result schemas, secret redaction, E2E refusal, and bounded partial output. The cross-repository contract check starts the actual Go stdio server and compares it with the hosted descriptors:

```bash
# from the rstream-nextjs repository
npm run test:mcp:contracts
```

That check classifies the current surface split explicitly: 41 shared tools, 24 device-only tools, and 5 hosted-only tools. A new tool or an accidental contract drift fails the check until its place in the surface model is deliberate.
